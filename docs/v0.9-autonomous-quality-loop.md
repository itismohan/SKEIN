# Skein v0.9 — Autonomous Quality Loop

## Purpose

v0.9 closes the v0.8 adaptive-context loop. Skein can now select context, invoke an agent, observe execution, evaluate the result, feed bounded relevance feedback into the context engine, and retry with newly selected context.

The control loop is:

**Task → Select → Execute → Observe → Evaluate → Learn → Re-select → Retry**

## Guardrails

- Maximum iteration count is explicit and bounded.
- Quality evaluation is injectable; the default evaluator only treats provider execution success as execution success, not proof of engineering correctness.
- Feedback is bounded to `[-1, 1]` and persisted append-only.
- Every iteration records the selected context, execution ID, quality signal, reward, and stop reason.
- No autonomous source-code mutation is performed by Skein itself.
- Provider credentials remain outside Skein telemetry.

## API

`run_quality_loop(...)` accepts a provider-neutral `AgentAdapter` and optional `QualityEvaluator`.

A quality evaluator returns:

- `passed`: whether the engineering quality gate passed
- `score`: normalized quality score from 0 to 1
- `reason`: explanation for the decision
- `retryable`: whether another iteration is allowed
- `checks`: structured evidence from tests, static analysis, review, or other validators

## Evidence

Loop records are written to `.skein/history/quality-loops.jsonl`. Existing connector telemetry and context-feedback ledgers remain the canonical supporting evidence streams.

v0.9 does not claim autonomous correctness merely because an LLM returns successfully. Strong claims require real task validators and paired evidence through the existing evaluation framework.
