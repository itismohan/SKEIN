# Skein v0.7 — Agent Adapter Layer

The Agent Adapter Layer separates **agent/provider invocation** from Skein's controlled execution, context envelope, and evidence contracts.

## Why adapters?

Skein should not become coupled to one model provider, coding agent, or SDK. Adapters provide a stable boundary:

```text
Skein Experiment
      |
      v
AgentRequest
      |
      +-------------------+-------------------+
      |                   |                   |
   CLI Agent           OpenAI             Anthropic
      |                   |                   |
      +-------------------+-------------------+
                          |
                    AgentResult
                          |
                    Connector Event
                          |
                    Evidence Engine
```

## Contract

Every adapter consumes an `AgentRequest` containing:

- task ID
- experiment arm
- agent identity
- task description
- Skein-selected context
- experiment metadata

It returns an `AgentResult` containing normalized:

- execution ID
- provider
- model
- outcome
- input/output/reasoning tokens
- latency
- response/error
- adapter metadata

## Built-in adapters

### CLI

`CliAgentAdapter` delegates to the existing controlled argv runtime. It is the recommended adapter for command-line coding agents and preserves the `shell=False` execution boundary.

### OpenAI

`OpenAIAdapter` accepts an injected provider callable. This intentionally keeps the OpenAI SDK optional while normalizing standard `usage.prompt_tokens`, `usage.completion_tokens`, and reasoning-token details through the existing connector contract.

### Anthropic

`AnthropicAdapter` accepts an injected provider callable and normalizes `usage.input_tokens` and `usage.output_tokens`.

## SDK integration pattern

Provider SDKs are injected rather than imported by core Skein:

```python
adapter = OpenAIAdapter(lambda request: provider_client(request))
result = adapter.invoke(agent_request)
persist_result(root, agent_request, result)
```

This keeps the core package provider-neutral and makes adapters straightforward to test with deterministic fakes.

## Security boundary

Skein does not execute provider-generated shell commands through this layer. CLI execution remains argv-based and uses `shell=False`. Network credentials and provider sandboxing remain outside the core adapter contract.

## Evidence boundary

An adapter normalizes what an agent reports; it does not assert task correctness. Task success must come from the experiment's outcome/quality signals and be evaluated by the v0.5 evidence engine.
