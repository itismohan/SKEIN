# Skein v0.7 — Provider Execution Bridges

Provider Execution Bridges connect real provider-compatible clients to Skein's
provider-neutral adapter and evidence contracts.

## Supported bridges

- `OpenAIExecutionBridge`: OpenAI Responses API or Chat Completions-compatible clients.
- `AnthropicExecutionBridge`: Anthropic Messages-compatible clients.

Provider SDKs are optional dependencies. The bridge accepts an already configured
client object, so credentials and client lifecycle remain outside Skein core.

## Example

```python
from skein.agent_adapters import AgentRequest
from skein.provider_bridges import OpenAIExecutionBridge, execute_and_persist

request = AgentRequest(
    task_id="T1", experiment="skein", agent="coder",
    task_description="Fix checkout validation",
    context="Relevant graph context...",
)
bridge = OpenAIExecutionBridge(client, model="your-model")
result = execute_and_persist(root, bridge, request)
```

## Execution flow

```text
Experiment assignment
        ↓
AgentRequest
        ↓
Provider Execution Bridge
        ↓
Real provider invocation
        ↓
Normalized AgentResult
        ↓
ConnectorEvent
        ↓
Evidence / Evaluation
```

## Security and evidence boundaries

Skein never stores provider credentials. It does not import provider SDKs by default,
execute provider-generated shell commands, or infer task correctness from a successful
API response. A provider response means the invocation completed; task success remains
an experimental quality signal evaluated separately.
