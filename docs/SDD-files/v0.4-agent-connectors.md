# Skein v0.4 — Agent Connector Layer

## Purpose

v0.4 establishes a provider-neutral boundary between agent runtimes and Skein. A connector converts provider/framework callbacks into the canonical `ConnectorEvent` contract. The connector layer does not require provider SDKs and does not claim certification of third-party clients.

## Event contract

Each event carries `task_id`, `experiment` (`baseline` or `skein`), `agent`, lifecycle/operation information, provider/model identity, token usage, optional cost/latency, outcome, handoff endpoints, tool name, graph version, metadata, and schema version.

## Built-in adapters

- `generic`: normalized payloads.
- `openai`: maps `usage.prompt_tokens`, `usage.completion_tokens`, and reasoning-token details where present.
- `anthropic`: maps `usage.input_tokens` and `usage.output_tokens`.

Adapters are intentionally dependency-free. A real runtime can call `normalize()` directly or send JSONL through the CLI.

## CLI

```text
skein connector-list
skein connector-import REPO EVENTS.jsonl --provider openai --experiment skein --task-id TASK-1 --agent coder
skein connector-summary REPO
```

## Evidence boundary

Connector ingestion proves normalization and durable capture. It does not by itself prove task success, production quality, provider billing accuracy, or reduction in cost. Those claims remain in Pilot Intelligence and require paired, reviewed evidence.
