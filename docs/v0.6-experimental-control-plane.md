# Skein v0.6 — Experimental Control Plane

Skein v0.6 turns pilot measurement into a reproducible experiment protocol. It does **not** claim causal impact by merely randomizing tasks; execution telemetry and matched outcomes are still required.

## Capabilities

- **Task corpus registry** — explicit task IDs, descriptions, difficulty, tags and eligibility.
- **Deterministic randomization** — seeded baseline/Skein allocation with a reproducible assignment map.
- **Experiment provenance** — provider, model, prompt fingerprint, graph head, repository commit, runtime and Skein version.
- **Confound detection** — flags missing or mismatched study controls instead of silently treating them as equivalent.
- **Power guidance** — transparent paired-continuous approximation for planning sample size; not a substitute for formal study design.
- **Reproducibility manifest** — canonical configuration hash, assignment map, task corpus, environment fingerprint and manifest integrity hash.
- **Evidence verification** — tamper detection for the generated manifest/evidence record.

## CLI

```text
skein experiment-init . --experiment-id my-study --seed 42
skein experiment-add-task . --task-id T001 --description "Implement checkout validation"
skein experiment-assign .
skein experiment-status .
skein experiment-report .
skein experiment-verify .
```

## Experimental discipline

The control plane deliberately separates **study design** from **agent execution**. It does not execute arbitrary commands, mutate repositories, or fabricate outcomes. Provider-native telemetry should be imported through the existing connector/telemetry layers and then evaluated by v0.5's matched-task engine.

### Primary metrics

The default planning set is context tokens, cost, and latency. Existing v0.5 evaluation also supports rework and handoff loss. Success remains a guardrail: efficiency gains are not considered useful if task success materially degrades.

### Randomization

Assignments are generated from a stable task-ID ordering followed by a seeded shuffle. The resulting assignment map is stored in the manifest. Re-running with the same corpus and seed produces the same assignment map.

### Confounds

A study should specify the repository revision, model/provider, prompt fingerprint and Skein graph head. Missing values are surfaced as confounds. A production experiment should also control for task difficulty, operator effects, model drift, tool versions and execution environment.

### Outliers

v0.6 defaults to **report-only** handling. Observations are not silently deleted. If an exclusion policy is adopted for a real study, exclusions should be pre-registered and retained in the evidence record.

## Evidence boundary

A randomized assignment protocol improves experimental validity, but it is not itself evidence of an improvement. v0.6 therefore reports provenance and study readiness separately from v0.5's statistical result. No production-quality or causal claim should be made without sufficient matched execution data and a successful quality guardrail.


### Paired design

The default design assigns **both Baseline and Skein arms to every eligible task**. Counterbalancing changes which arm is first for alternating randomized tasks. This produces matched observations suitable for the v0.5 paired evaluation engine.
