# Skein v1.0 — AI-DLC Control Plane

Skein v1.0 turns the accumulated graph, specification, traceability, adaptive context, agent execution, quality evidence, and governance capabilities into one explicit AI-DLC control plane.

## Lifecycle

`Specify → Plan → Select Context → Execute → Observe → Evaluate → Approve → Finalize`

The control plane owns lifecycle state and evidence; specialized subsystems continue to own their domain responsibilities.

## State machine

`created → planned → executing → evaluating → approval_required → approved → completed`

Failure, rejection, and cancellation are terminal states. Invalid transitions are rejected.

## Governance

- Risk is explicit: low, medium, high, critical.
- Approval is explicit and attributable to an actor.
- Quality evidence is recorded separately from provider execution success.
- Event history is append-only JSONL.
- A deterministic integrity fingerprint is provided for exported evidence.
- The control plane never silently mutates source code or bypasses existing policy/sandbox boundaries.

## CLI

```text
skein control-init
skein control-plan
skein control-begin
skein control-evaluate
skein control-approve
skein control-finalize
skein control-reject
skein control-status
skein control-export
```

## Architectural boundary

The v1.0 control plane is an orchestration and governance layer, not a replacement for the graph store, SDD validator, adaptive context engine, agent adapters, autonomous quality loop, or provider bridges. Each remains independently testable and auditable.

## Production principle

A model response is not evidence of engineering correctness. Completion requires quality evidence and, where policy requires it, explicit human approval.
