# Skein v0.8 — Adaptive Context Intelligence

## Goal

v0.8 turns Skein from a context provider into an **adaptive context selector**. Instead of passing a fixed graph slice to every agent, Skein ranks available engineering evidence for the current task and selects the smallest useful set under a token budget.

## Design principles

1. **Deterministic first** — selection is reproducible and explainable without requiring an embedding service or LLM.
2. **Graph-native** — relevance starts from the existing Living Specification / engineering graph rather than a disconnected memory store.
3. **Budget-aware** — context selection is explicitly bounded by tokens.
4. **Diverse evidence** — greedy selection slightly favors different node types so a context is not dominated by one artifact class.
5. **Learning with guardrails** — explicit feedback changes future ranking, but feedback is bounded to [-1, 1] and cannot overwhelm task relevance.
6. **Evidence-preserving** — every selection records its candidates, scores, reasons, budget and selection fingerprint.

## Scoring

Each candidate receives:

`score = 0.72 * lexical_relevance + 0.18 * graph_connectivity + 0.10 * bounded_feedback`

A small diversity bonus is applied during greedy selection. This is intentionally transparent and can later be replaced or augmented by learned retrieval models.

## CLI

```bash
skein context-select --task-id T1 --query "create order payment" --budget 1200
skein context-render --task-id T1 --query "create order payment" --budget 1200
skein context-feedback --selection-id <id> --node function:create_order --reward 1 --task-id T1 --reason "directly used"
skein context-health
```

## Persistence

- `.skein/history/context-selections.jsonl` — immutable selection events.
- `.skein/history/context-feedback.jsonl` — explicit relevance feedback.

## v0.8 boundary

The current implementation is **adaptive retrieval**, not autonomous reinforcement learning. It does not silently infer user preference from arbitrary model output. Feedback must be explicit. External vector databases and provider-specific ranking models are not required.

## Success criteria

- Reduce context tokens relative to the fixed v0.7 graph-context strategy.
- Preserve or improve structural retrieval F1.
- Produce an explanation for every selected evidence item.
- Keep selection within a declared budget.
- Demonstrate that relevance feedback changes subsequent rankings.
- Preserve append-only evidence needed for later evaluation.
